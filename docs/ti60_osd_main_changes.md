# `ti60-osd-main` 需要的改动清单

> **本文是交付物**，面向 `ti60-osd-main` 团队，随 `add-quad-osd-overlay` 变更移交。
> 本文自包含 —— 收件方不需要访问本仓库。
>
> **背景一句话**：TI60 侧的 OSD 从"单片全屏掩膜"改为"**4 路互不重叠的 1 bit/像素窗口**"，
> 地址、位宽、行跨距、寄存器映射、协议应答长度全部随之变化。
> `ti60-osd-main` 只提供**构图机制的代码**，其协议层（`proto.c`、`dispatch.c`）
> 与应答布局一概不采用。

## 1. 八项改动

| # | 现状 | 目标 | 依据 |
|---|---|---|---|
| 1 | `OSD_CANVAS_W 720`、`OSD_BLOCK_BYTES 720*208` | 画布收窄到 **544**，`OSD_BLOCK_BYTES` 随之变 544×208 | 单路上限 544×288 |
| 2 | 8 bit/像素（`OSD_PIXEL_FG 0xFF`） | **1 bit/像素**，行按 68 字节打包，**bit 7 最左** | 位图格式 |
| 3 | `OSD_BLOCK0_ADDR 0x00F00000` / `BLOCK1_ADDR 0x00F24900` | 改用**菜单承载路 OSD1**：`0x00A4_0000` / `0x00B4_0000` | 地址表第 2 行 |
| 4 | `REG_OSD_COMMIT/BASE_LO/BASE_HI` 占位偏移 | 改为 12 字映射：提交 → `COMMIT` 的 `bit31`；**删除 `BASE_LO`/`BASE_HI`**（基址不可运行时配置）；画布切换 → `OSD[1].CTRL.buffer_select` | 寄存器映射 |
| 5 | `canvas_select_block()` 独立接口 | 收敛为写 `OSD[1].CTRL.buffer_select` | 同上 |
| 6 | `PROTO_QUERY_RESP_LEN 14`；`ui_query_view` 填 11 字节 + 3 补零 | 改为 **12 字节 body**。`ui_query_view` 里 `resp[0..7]`（`page_id`/`sel`/`flags`/`v0..v3`）**顺序恰好已正确、保持不变**；只在调用侧前置 `04 08 02 FF` 四字节，并删去 `item_count`（原 `resp[8]`）与 `fw_version`（原 `resp[10]`） | 0x04 应答口径 |
| 7 | `UI_FLAG_SELECTED 0x01` | 语义改为 **UI 显示**（改名）；`ui.c:229` 的 `*` / `>` 前缀选择改用 `selected_item` + `bit1` | 协议 §3.1 |
| 8 | `UI_FLAG_LANG_RU 0x04`、`UI_FLAG_MASK 0x07` | **删除语言位**（`flags` 不承载语言）；`UI_FLAG_MASK` → `0x03`；`ui.c:32` 的 en/ru 选择固定为英文 | 协议 §3.1 |

（行号取自本次评审的版本；若源码已变动，请按符号名定位。）

## 2. 第 6 项为什么是 12 字节

权威口径是上位机工具与协议文档，两者逐字节一致。工具侧校验
（`tools/send_ui_via_adb.py`）是硬校验，任何一项不符都会抛
`UI命令失败`：

```
期望整帧长度  : 18 字节（body 12）
期望 body 长度: 12
body[:3]      : 04 08 02      （大类、子项、应答类型）
body[3]       : FF            （成功判据）
body[4:6]     : page_id  u16BE
body[6]       : selected_item
body[7]       : flags         （bit0 = UI 显示，bit1 = 数值编辑）
body[8:12]    : image_enhance, contrast, image_brightness, screen_brightness
CRC           : CRC-16/CCITT 覆盖**完整 12 字节 body**
```

即 `04 08 02 FF | page_id(2) | sel | flags | v0 v1 v2 v3`，正好 12 字节，
**没有** `item_count`、**没有** `fw_version`。

其余子项的应答是 **10 字节整帧 / 4 字节 body**：`04 | 子项 | 02 | 状态`。
这一支与现有的 `protocol_build_ack()` 输出逐字节相同（含 CRC 覆盖范围与
成功值 `0xFF`），一行都不用改；**只有 QUERY_VIEW 需要新的变长构造**。

## 3. 子命令范围（本期）

工具揭示了 **8 个子命令**，而协议文档只描述了 3 个、`ti60-osd-main` 也只实现了 3 个：

| sub | 名称 | 本期 |
|---|---|---|
| `0x01` | show / hide | **不纳入** |
| `0x02` | key（旧按键，保留供人工操作） | **不纳入** |
| `0x03` | 方位角 / LRF / 俯仰 / 横滚 + `valid_flags` | **不纳入** |
| `0x04` | clear | **不纳入** |
| `0x05` | 测距标记坐标（11..708 / 11..564） | **不纳入** |
| `0x06` | SET_VIEW | 在范围内 |
| `0x07` | SET_IMAGE_VALUES | 在范围内 |
| `0x08` | QUERY_VIEW | 在范围内 |

`0x01`–`0x05` 按**只解析、不应答、不计入坏包**处理 —— 避免在别人（或未来的自己）
的读取窗口里插进意外字节。将来纳入 `0x05` 时，需先确认它与画面内缩边界及 4 个 OSD
窗口的关系（其坐标范围 11..708 / 11..564 正是画面内缩边界的形状）。

## 4. 地址与格式（供第 1–3 项对照）

```
位图 = 1 bit/像素，行内 bit 7 最左，行跨距 = width/8 字节（紧凑，行间无空隙）
byte_addr(x, y) = base(i, buf) + y * (width_i/8) + (x >> 3)
bit_index       = 7 - (x & 7)
bit = 1 → 输出纯白 16'h80EB；bit = 0 → 视频透传；无 alpha

base(i, buf) = (buf ? 0x00B0_0000 : 0x00A0_0000) + i * 0x0004_0000
  OSD0  A=0x00A0_0000  B=0x00B0_0000   544×288   （UART 上传固定路）
  OSD1  A=0x00A4_0000  B=0x00B4_0000   544×208   （菜单承载路 ← 第 3 项改到这里）
  OSD2  A=0x00A8_0000  B=0x00B8_0000   544×288
  OSD3  A=0x00AC_0000  B=0x00BC_0000   544×288
一缓冲大小：544×288/8 = 19,584 B；544×208/8 = 14,144 B
```

## 5. 其它必须知道的两条

1. **窗口重叠由软件保证**。硬件不检测、不拒绝、不报错；重叠时的输出不在契约范围内。
   菜单承载路与掩膜上传路已由地址分配隔开（OSD1 / OSD0），不要再把两者配成同一路。
2. **上传协议只有一个目标**（OSD0），不增加区域索引字段、也不以目标地址表达区域选择。
   多路场合由软核直接寻址，不经由上传协议。
