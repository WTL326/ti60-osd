# OSD 位图接口契约（RTL ↔ 固件 / 上位机）

> **本文是交付物**：面向固件团队与上位机团队，随 `add-quad-osd-overlay` 变更发布。
> 内容为**接口约定**（地址、格式、寄存器、责任边界），不含 RTL 内部实现理由——
> 后者见变更内的 `design.md` D1/D3/D6/D11。
>
> **取代声明**：本文取代 `docs/SOFTCORE_DESIGN.md` §2.3（掩膜上传）与
> `docs/memory_axi.md` 中改造前的掩膜描述。**8-bit/像素、legacy/raw 双模式、
> 画布位于 `0x0040_0000`/`0x0050_0000` 这三条已全部作废**，以本文为准。

## 1. 位图格式

| 项 | 约定 |
|---|---|
| 位宽 | **1 bit/像素**（不是 8 bit） |
| 行内打包 | 按字节打包，**bit 7 对应行内最左像素**（MSB-first） |
| 行跨距 | **紧凑：`width/8` 字节**（不是固定 512，也不是 `width`） |
| 位 = 1 | 输出纯白 `16'h80EB`（YUV422：Y=0xEB, Cb=Cr=0x80） |
| 位 = 0 | 视频像素**原样透传** |
| alpha | **不存在**。没有半透明通路，不要按"灰度值即透明度"来生成位图 |

寻址式（`i` = 路号 0..3，`buf` = 0=A / 1=B）：

```
byte_addr(x, y) = base(i, buf) + y * (width_i / 8) + (x >> 3)
bit_index       = 7 - (x & 7)
```

一条 544 宽的行占 68 字节；位图在内存中**逐行连续**（第 `y+1` 行紧接第 `y` 行），
没有行间空隙。

> **位打包是上位机的责任**。RTL 只按字节读写，不解析位序；`RtlMaskUartAxiWriter`
> 同样只做字节透传。打包实现见 `tools/send_mask_via_adb.py`
> （单元测试 `tools/test_mask_packing.py` 用 5 个用例钉死位序：
> 最左像素 → `0x80`、最右 → `0x01`、交替 → `0xAA`）。

## 2. 地址表

`base(i, buf) = (buf ? 0x00B0_0000 : 0x00A0_0000) + i * 0x0004_0000`，
即 `0xA0` 段装 4 路的 **A** 缓冲、`0xB0` 段装 4 路的 **B** 缓冲：

| 路 | Buffer A | Buffer B | 尺寸（编译期参数） | 一缓冲字节数 |
|---|---|---|---|---|
| OSD0 | `0x00A0_0000` | `0x00B0_0000` | 544×288 | 19,584 |
| OSD1 | `0x00A4_0000` | `0x00B4_0000` | 544×208 | 14,144 |
| OSD2 | `0x00A8_0000` | `0x00B8_0000` | 544×288 | 19,584 |
| OSD3 | `0x00AC_0000` | `0x00BC_0000` | 544×288 | 19,584 |

- 尺寸为**综合期参数**（RTL 参数 `OSD0..3_WIDTH/HEIGHT`），**改尺寸要重新综合**。
  上表是本位流的实际取值（取自 `src/top.v` 例化处的字面量）。
- 单个槽位固定 256 KB，实际只用 19 KB 量级。**这是刻意的**：换取基址表长期稳定、
  不随尺寸参数变动。不要把槽位间距当作可用空间。
- **不提供运行时尺寸寄存器，也不提供运行时基址寄存器**。需要知道尺寸时按本文约定；
  上位机无法从 RTL 侧自查位流用的是哪组尺寸（已知代价，见变更 Risks）。

## 3. 窗口划分（软件必须遵守）

| 用途 | 路 | 谁写 |
|---|---|---|
| 掩膜上传（UART 协议固定目标） | **OSD0**（`0x00A0_0000`/`0x00B0_0000`） | `tools/send_mask_via_adb.py` 经 RTL 状态机，或固件经 AXI |
| 菜单画布承载 | **OSD1**（`0x00A4_0000`/`0x00B4_0000`） | 固件 |
| 未分配 | OSD2 / OSD3 | 固件（可自由寻址） |

两条硬约束：

1. **上传固定路与菜单承载路必须是不同的两路**。上传协议不带区域索引、也不以目标地址
   表达区域选择（帧格式不变），它**只写 OSD0**；若把菜单也放在 OSD0，上传会静默覆盖菜单画布。
2. **上位机与固件必须保证同时使能的窗口两两不重叠**。硬件**不检测重叠、不拒绝、
   不报错**——重叠时的输出不在契约保证范围内（RTL 内部按路号小者优先，但这不是契约）。

## 4. 寄存器映射（`0xE1043000`，12 个字）

| 偏移 | 名称 | R/W | 内容 |
|---|---|---|---|
| `+0x00` | `COMMAND` | W | `bit31` = commit，`bit0` = global_enable |
| `+0x04` | `STATUS` | R | `{commit_count[15:0], 13'd0, pending, 1'b0, applied_global_enable}` |
| `+0x08` | `CANVAS` | R | `{16'd720, 16'd576}`（画面尺寸，与窗口无关） |
| `+0x0C` | `ACTIVE` | R | `{24'd0, applied_enable[3:0], applied_buffer_select[3:0]}` |
| `+0x10 + 8*i + 0x0` | `OSD[i].POS` | W | `{8'd0, top[11:0], left[11:0]}`，**均为有符号** |
| `+0x10 + 8*i + 0x4` | `OSD[i].CTRL` | W | `{30'd0, buffer_select, enable}` |

`+0x30` 及以上读 0。

**读回位域**（注意不要与写入顺序搞混）：

- `STATUS.pending` = `bit2`；`STATUS.applied_global_enable` = `bit0`；
  `STATUS.commit_count` = `bit31:16`。
- `ACTIVE.applied_enable` = `bit7:4`（**高半字节**）；
  `ACTIVE.applied_buffer_select` = `bit3:0`（低半字节）。
- `POS.left` 与 `POS.top` 是**有符号 12 bit**，允许负值把窗口部分移出画面，
  越界部分由硬件裁剪（该处视频透传），不需要上位机预裁剪。
- `POS`/`CTRL` 是**只写**的，读回 0。需要确认实际生效值时读 `ACTIVE`——
  它给的是**已生效**的值，比"刚写进去但还没提交"的值更有意义。

### 提交协议

1. 写 4 路的 `OSD[i].POS` / `OSD[i].CTRL`（**只改暂存区，不生效**，任何一路都不受影响）；
2. 写 `COMMAND = 0x8000_0000 | global_enable` 提交；
3. 轮询 `STATUS.pending`（`bit2`）直到为 0 —— 表示已在帧边界整体生效，
   此时 `STATUS.commit_count` 加 1。

- 提交是**原子的**：一次 `COMMAND` 写把 4 路的位置/使能/缓冲选择一起推出去，
  不会出现"第 2 路生效了、第 3 路还没"的中间态。
- `pending` 未清时**拒绝**新的提交（`commit_count` 不变、已提交内容不被破坏）。
  因此流程必须是"提交 → 等 pending 清 → 再提交"。
- 生效点在**完整帧边界**，整帧使用同一份配置。不提供"立即生效"。

## 5. 两条上传路径

`rtl_mask_mode` 选择当前生效的**上传者**（不是寻址模式，寻址只有一套）：

| `rtl_mask_mode` | 路径 | 说明 |
|---|---|---|
| `1'b0`（当前位流） | 软核 AXI | 固件写 `MaskControlRegs` 并在帧边界生效；位图数据由固件自己写进上表槽位 |
| `1'b1` | RTL UART 状态机 | `RtlMaskUartAxiWriter` 接收 0x06 类 UART 帧，**只写 OSD0** |

两条路径写的是**同一批槽位**，选择哪条不影响地址计算。

## 6. 软件责任边界（不重叠）

**硬件负责**：

- 按上表寻址、按 1 bpp 取位、把位 = 1 的像素替换为 `16'h80EB`；
- 窗口位置的越界裁剪（含负坐标）；
- `pending` 期间拒绝二次提交；
- 整帧在 SOF 边界切换缓冲（无撕裂）。

**软件负责**：

- 生成 1 bpp、MSB-first、紧凑跨距的位图（位打包的全部责任）；
- 保证同时使能的窗口两两不重叠；
- 保证上传目标只有 OSD0、菜单只放 OSD1；
- 提交时序（写暂存 → 提交 → 等 `pending` 清）；
- 位图内容与尺寸参数的一致性（硬件不知道位图里有多少有效数据）。

**明确不在本契约内**：

- 硬件不做重叠检测；
- 硬件不提供尺寸/基址回读；
- 硬件不做 alpha 混合。
